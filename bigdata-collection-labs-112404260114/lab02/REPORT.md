答：每条记录对应 8 个参数的方式是：先用 csv.DictReader 读取 data/houseinfo.csv 并检查表头，再按 CSV_HEADERS 的固定顺序（title、house、address、struct、area、floor、maketime、price）把每行整理成含 8 个值的列表；INSERT 语句写成 INSERT INTO houseinfo (title, house, address, struct, area, floor, maketime, price) VALUES (%s, ×8)，8 个 %s 参数位置与 8 个字段一一对应，实际值通过 executemany(INSERT_SQL, records) 的第二个参数传入，不用字符串拼接。成功时调用 conn.commit() 提交事务并查询总条数确认；失败时在 except 里调用 conn.rollback() 回滚本次事务中未提交的修改；无论成功失败都在 finally 里先 cursor.close() 再 conn.close() 释放资源。再次运行时，程序先 SELECT 把库内已有记录的 8 个字段取回组成集合 existing，CSV 中每条记录也转成同样的元组，只插入 existing 中不存在的记录。本次实际运行验证了这一点：首次运行后库内共 498 条，同批数据再次运行时输出“库内已有 498 条，本次待插入 0 条、正式写入 0 条、入库后 498 条”，条数未增加，说明重复插入被成功避免。

## 思考题

1. 本次怎样实现下一页采集？结合自己的代码说明。

   答：每解析完一页，用 soup.select_one("a.next.next-active") 定位处于活动状态的“下一页”按钮，用 next_node.get("href") 取得相对地址 ?page=2（注意 get_text() 取到的是“下一页”文字，get("href") 取到的才是地址），再用 next_url = urljoin(current_url, href) 把相对地址补全成完整地址，赋给 page_url 进入 while 循环的下一轮请求。停止条件是：当某页找不到活动的下一页按钮（next_node is None）且分页区域 ul.page 仍然存在时，说明“下一页”按钮已禁用、到达末页，输出“采集完成”后正常结束；此外还设置了 MAX_PAGES = 30 安全上限、visited 集合防重复地址、地址前缀检查防越出教学站。

2. 旧代码把 out_list 定义在全局。你把结果列表放在哪里？为什么？

   答：我把结果列表 all_rows 定义在 crawl_all() 函数内部，作为局部变量，由函数通过 return all_rows 返回，外面用 results = crawl_all(...) 接收。原因是：结果列表放在全局时，多次运行程序会往同一个列表里继续追加，旧数据和新数据混在一起，还会被其它代码意外修改；放在函数内部后，每次调用 crawl_all() 都会创建一个全新的列表，多次运行互不污染，数据的作用范围清晰，也符合“谁使用谁创建”的编程习惯。

3. 你怎样获取建造年代？节点缺失或顺序改变时，怎样处理？

   答：建造年代在属性组 p.property-content-info-text 的第 5 项（下标 4），我用 row.select("p.property-content-info-text") 取出整个列表后，先用 if len(info_list) >= 5 判断长度再取下标，而不是取到再说；长度不足时 maketime 保持预先初始化的空字符串，即节点缺失时填空字符串，不会报下标越界错误。如果网页结构改变、属性顺序调整，按固定下标取值就可能取错字段，所以取值前我先在浏览器里核对过每页属性组的固定顺序（户型、面积、朝向、楼层、建造年代），并把面积、楼层、年代与网页逐条对照过；更稳妥的做法是解析每个标签自身的文字特征（如“年建造”结尾）来匹配字段，而不单纯依赖位置。
